# 버스 경로 비교 및 구간별 탑승 알림

> 상태: 변경 기획 / 2026-10-19  
> 대상: iOS, Android, Web App  
> 핵심: 실시간 환승 연결을 고려한 버스 경로 비교 + 구간별 도착 5분 전 알림

## 1. 제품 목적

사용자가 출발지와 목적지를 선택하면 직행 및 환승 경로를 생성한다. 출발 시간대별로 탈 수 있는 차량 조합, 환승 대기시간, 전체 소요시간 및 목적지 도착 시각을 비교하고 사용자가 경로와 버스를 선택한다. 이동을 시작한 뒤 첫 승차와 각 환승 구간에서 탈 버스가 해당 승차 정류장에 도착하기 5분 전에 알린다.

이전의 정류장·노선 개별 등록 및 정류장 반경 30m 진입 중심 기획을 대체한다. 위치는 출발지 입력과 이동 진행을 돕는 보조 수단이며 30m 진입을 알림의 필수 조건으로 두지 않는다.

### 핵심 사용자와 사용 맥락

주 대상은 대중교통으로 출퇴근하는 직장인과 등하교하는 학생이다.

- 직장인: 집↔회사 경로를 저장하고 출퇴근 시간대별 직행·환승을 비교한다.
- 학생: 집↔학교 경로를 저장하고 요일별 수업 일정에 맞춰 이용 시간대를 관리한다.
- 공통 목표: 반복 검색을 줄이고, 환승 대기와 목적지 도착 시각을 비교하며, 이동 중 화면을 계속 보지 않아도 탈 버스를 알림으로 확인한다.
- 우선 UX: 저장 경로 바로 실행, 가는 길/오는 길 구분, 요일별 시간대 설정, 출발 시간대별 비교, 구간별 탑승 알림.
- 정시 도착 판단을 돕도록 목표 도착 시각과 예상 도착 시각을 비교하는 기능을 후속 확장으로 검토한다.

## 2. 대표 경로

| 후보 | 이동 순서 |
|---|---|
| 환승 1 | A → a 버스 → B → b 버스 → D |
| 환승 2 | A → c 버스 → C → d 버스 → D |
| 직행 | A → e 버스 → D |

대문자는 정류장, 소문자는 버스 노선을 뜻한다. 노선마다 방향과 개별 차량/운행을 구분한다. a·b뿐 아니라 c·d·e 모두 현재 도착 정보와 다음 차량을 고려한다.

첫 번째 버스가 빨리 온다는 이유만으로 가장 빠른 경로로 판단하지 않는다. 환승 차량을 놓쳐 다음 배차까지 기다린다면 늦게 출발하는 다른 환승 조합이나 직행이 먼저 도착할 수 있다.

## 3. 사용자 흐름

1. 출발지와 목적지를 선택한다. 정류장 직접 선택을 지원하고 장소 선택 시 연결되는 승하차 정류장과 도보 구간을 표시한다.
2. 지금 출발 또는 날짜·출발 시각을 선택하고 여러 출발 시간대를 비교한다.
3. 직행·환승 후보와 구간별 차량 도착 시각, 환승 대기, 전체 소요시간, 목적지 도착 시각을 확인한다.
4. 사용자가 경로와 구간별 버스를 선택한다. 같은 목적지로 연결되는 대체 노선도 허용 후보로 선택할 수 있다.
5. 이동 시작 후 첫 승차 버스의 도착 5분 전 알림을 받는다.
6. 탑승을 확인하면 현재 구간을 주행 중으로 바꾸고 다음 환승 연결을 갱신한다.
7. 환승 구간에서는 선택한 다음 버스의 도착 5분 전 알림을 받는다.
8. 지연·놓침이 발생하면 이후 연결과 도착 시각을 다시 계산하고 사용자에게 대안을 제안한다.
9. 목적지 도착 또는 사용자 종료 시 추적과 이후 알림을 중단한다.

## 4. 경로 탐색과 시간 계산

### 필수 입력

- 출발·목적 정류장 및 위치, 노선별 정차 순서와 방향
- 출발 날짜·시각 및 서비스 지역의 시간대
- 노선/정류장별 실시간 도착 예정 시각과 가능한 경우 차량·운행 ID
- 구간별 예상 주행시간
- 환승 하차 지점에서 다음 승차 지점까지 도보시간 및 환승 여유시간
- 운행일·시간대별 시간표, 배차간격, 첫차·막차 및 운행 상태
- 데이터 출처, 기준 시각과 유효기간

### 구간별 연결 규칙

- 첫 구간의 탑승 가능 시각 = 선택한 출발 시각 + 첫 정류장까지 도보시간.
- 다음 구간의 탑승 가능 시각 = 이전 차량의 하차 예정 시각 + 환승 도보시간 + 환승 여유시간.
- 해당 시각 이후 승차 정류장에 도착하는 차량을 연결 후보로 평가한다.
- 현재 조회되는 첫 차량을 놓치면 다음 차량을 비교한다. 같은 노선의 이후 차량도 별도 후보로 평가한다.
- 전체 소요시간에는 첫 대기, 모든 주행·도보·환승 대기 및 목적지까지 도보를 포함한다.
- 구간마다 계산한 시각을 다음 구간으로 전달한다. 현재 시점의 각 노선 ETA를 단순 합산하지 않는다.
- 동일 노선이라도 방향, 분기, 급행 정차 여부가 다르면 별도 연결로 판단한다.
- 순환·중복 경로를 억제하고 환승 횟수와 도보 범위의 탐색 상한은 설정값으로 관리한다.

### 계산 예시

아래 시간은 설명용 예시이며 실제 운행 데이터가 아니다.

| 항목 | 현재 08:00 기준 |
|---|---|
| A에 a 버스 도착 | 08:03 |
| a를 타고 B까지 | 10분 → 08:13 하차 |
| 환승 도보 + 여유 | 2분 → 08:15부터 탑승 가능 |
| B의 b 버스 | 08:12 차량은 탈 수 없음 |
| 다음 b 버스 | 08:32라면 환승 대기 17분 |
| 이후 비교 | c·d 경로 및 직행 e의 목적지 도착 시각과 비교 |

08:32가 실시간 관측이면 실시간으로 표시한다. 08:12에 배차간격 20분을 더한 값이라면 배차 추정으로 표시한다. 배차간격을 정확한 운행 시각으로 취급하지 않는다.

### 데이터 우선순위와 불확실성

- 유효한 실시간 차량 예측을 우선 사용한다.
- 미래 출발이나 실시간 조회 범위 밖 구간은 날짜·요일·시간대에 맞는 시간표를 사용한다.
- 시간표가 없으면 알려진 배차간격으로 추정하고 추정 근거 및 범위를 표시한다.
- 배차간격조차 없거나 막차 이후이면 확정 연결로 제시하지 않는다.
- 실시간 차량 정보가 일부만 제공될 경우 뒤 차량이 없다고 단정하지 않는다.
- 차량 지연, 교통 상황 및 데이터 갱신에 따라 환승 가능 여부와 경로 순위가 달라질 수 있음을 표시한다.
- 가까운 환승 연결은 여유시간과 데이터 신뢰도를 함께 보여준다.

## 5. 비교와 선택 화면

경로 카드에는 출발 시각, 목적지 도착 시각, 전체 소요시간, 환승 횟수, 도보시간과 총 대기시간을 표시한다. 상세 화면에는 구간별 승하차 정류장, 방향·행선지, 선택 차량 도착 시각, 환승 대기·여유시간과 다음 차량 정보를 표시한다.

사용자는 출발 시간대를 바꾸거나 직행·환승을 비교하고 각 구간에서 이용할 버스 및 허용할 대체 노선을 선택한다. 빠른 도착·적은 환승·짧은 도보 등의 비교 기준을 제공하되 최종 선택은 사용자에게 맡긴다. 예상 시간이 갱신되어도 선택 경로를 동의 없이 바꾸지 않는다.

## 6. 구간별 알림과 이동 상태

- 이동 상태: 출발 대기 → 첫 버스 대기 → 탑승 중 → 환승 이동/대기 → 다음 버스 탑승 → 도착. 취소 상태도 별도로 둔다.
- 기본 알림 기준은 선택 차량이 해당 구간의 승차 정류장에 도착하기 5분 전이다.
- 첫 승차와 모든 환승 구간에 같은 기준을 적용한다.
- 이동 시작 또는 다음 구간 활성화 시 이미 도착 5분 이내라면 남은 시간을 즉시 안내한다.
- 아직 이전 버스에 탑승 중이어도 다음 환승 버스의 5분 전 시점에는 환승 준비 알림을 제공할 수 있다. 실제 환승 가능 여부를 다시 확인하고, 연결 불가 차량에는 탑승 가능 알림을 보내지 않는다.
- 알림에 노선·방향, 승차 정류장, 남은 시간, 첫 승차/환승 구분과 데이터 시각을 표시한다.
- 같은 이동 세션·구간·차량·알림 종류별 중복을 방지한다. 차량 ID가 없으면 대체 식별 방식과 낮은 신뢰도를 관리한다.
- 버스 놓침이나 연결 불가 발생 시 다음 차량과 대체 경로를 제안한다. 사용자가 선택하면 이후 알림 대상을 교체하고 오래된 예약 알림을 취소한다.
- 자동 위치 판정이 불확실하면 탑승·하차·환승을 사용자가 직접 확인할 수 있다.
- 정류장 근처 여부는 보조 정보로만 활용하며 반경 밖이라는 이유로 활성 이동의 알림을 차단하지 않는다.
- 종료·도착한 이동의 알림은 취소한다.

## 7. 화면 구성과 디자인 방향

| 화면 | 핵심 내용 |
|---|---|
| 홈 | 출발지·목적지, 출발 시각, 최근/저장 이동 |
| 경로 비교 | 시간대별 직행·환승 후보, 도착 시각·대기·환승 횟수 |
| 경로 상세 | 구간별 타임라인, 차량 선택, 다음 배차와 환승 여유 |
| 이동 중 | 현재 구간, 다음 승차·환승 버스, 갱신된 도착 시각 |
| 탑승 알림 | 첫 승차/환승 정류장과 버스 도착까지 남은 시간 |
| 저장 경로·시간 설정 | 자주 가는 출발지/목적지, 요일·시간대, 알림 활성화 |
| 설정 | 알림·위치 권한, 개인정보, 데이터 제공 범위 |

아이보리 배경·딥 틸 기본 동작·라임 알림 강조를 유지한다. 큰 도착 시각과 구간별 타임라인으로 비교를 돕고, 실시간·시간표·배차 추정을 명확히 구분한다. 기존 생성 이미지에는 이전 컨셉이 포함되어 있으므로 새 화면의 기능 사양으로 사용하지 않는다.

## 8. 시스템 구성 및 데이터 모델 제안

- 교통 데이터 어댑터: 지역별 정류장·노선·운행일·실시간 차량 정보를 공통 형식으로 변환한다.
- 경로 탐색기: 정류장 연결과 환승 도보를 이용해 직행·환승 후보를 생성한다.
- 시간 기반 연결 평가기: 구간별 탑승 가능 차량과 이후 배차를 계산한다.
- 이동 세션 관리: 선택 경로·차량, 현재 구간, 탑승 확인 및 대체 선택을 관리한다.
- 알림 처리: 구간별 5분 기준, 갱신·취소와 중복 방지를 처리한다.
- 캐시·운영: 제공자 갱신 주기, 조회 제한, 오류·데이터 신선도를 관리한다.

| 모델 | 주요 내용 |
|---|---|
| Stop / Route / RouteStop | 좌표·방향·정차 순서·승하차 가능 여부 |
| ServiceSchedule / Headway | 운행일·시간대·시간표·배차간격 및 출처 |
| VehicleArrival | 차량/운행·정류장·도착 시각·원본 갱신 시각 |
| JourneyRequest | 출발·목적지·출발 시각·환승 및 도보 조건 |
| JourneyOption / Leg | 구간별 도보·차량·승하차·대기·예상 도착 및 추정 근거 |
| JourneySession | 선택 경로·허용 대체 노선·현재 구간·상태 |
| AlertRecord | 세션·구간·차량·알림 종류·발송/취소 상태 |

위치는 필요한 시점에 최소한으로 사용하고 이동 경로의 영속 저장을 기본으로 요구하지 않는다. 기존 앱·서버의 모델과 API는 새 기획에 맞는 별도 구현 검토가 필요하다.

## 9. 플랫폼과 운영 고려

iOS·Android·Web 모두 출발/목적지 선택과 경로 비교를 목표로 한다. 백그라운드 실행, 위치 갱신 및 알림 전달 범위는 플랫폼별로 검증한다. 화면이 닫혀도 항상 5분 전에 전달된다고 약속하지 않는다.

앱 종료 상태의 서버 알림은 선택된 이동 세션과 정류장·차량 구독을 중심으로 설계하고 불필요한 위치 전송을 피한다. 위치 권한이 없어도 수동 출발지 선택과 진행 확인을 지원하는 방향으로 설계한다.

공급자 장애·오래된 데이터·차량 식별 불가·시간표 누락·운행 종료는 사용자에게 명시한다. 예측 불가 상태를 정확한 도착 시각으로 표시하지 않는다. API 이용 조건·쿼터·보안·개인정보 및 위치 처리 관련 출시 요건은 실제 데이터 흐름에 맞춰 확인한다.

## 10. 구현 단계와 남은 결정

1. 첫 출시 지역의 경로 탐색·실시간 도착·시간표·배차 데이터 확보 가능성을 확인한다.
2. 직행 및 1회 환승부터 시간대별 후보 생성과 구간 연결 계산을 구현한다. 이후 다중 환승으로 확장한다.
3. 경로/차량 선택과 수동 탑승 확인 기반 이동 세션 및 구간별 알림을 구현한다.
4. 실시간 재계산, 대체 노선 선택 및 위치 기반 진행 보조를 확장한다.
5. 플랫폼별 백그라운드 알림과 실제 환승 연결 정확도를 검증한다.

남은 결정: 첫 출시 지역·데이터 제공자, 초기 환승 상한·도보 범위, 기본 환승 여유시간, 시간대 비교 단위, 반복 이동 시작 방식, 플랫폼별 지원 범위.

## 11. 기획 검토 기준
