# 버스 타이머 상세설계

## 범위와 배포 주소

직장인·학생의 반복 이동을 위해 정류장 기반 직행·최대 2회 환승 경로와 구간별 버스를 비교·선택한다. 배포 주소는 `https://app.bluewaikiki.top/bustimer/`, API는 `/bustimer/api/`다. 도메인 루트의 앱 목록과 가계부 `/ledger/`는 별도 서비스다.

실행 구성: Caddy → Ubuntu Node.js 24 HTTP 서버 → SQLite. Flutter Web 산출물은 같은 서버가 `/bustimer/`에서 제공한다. 모바일도 동일 API에 접속한다. Cloudflare Worker·D1은 이전 구성으로 분리한다.

## 경로 엔진

1. 출발/도착 정류장, UTC 출발 시각, 비교 개수(1~8), 간격(5~120분), 환승 상한(0~2), 환승 여유(0~900초)를 검증한다. 검색은 현재부터 7일 이내로 제한한다.
2. 해당 기간 시간표의 운행별 정차 목록을 읽고 상류→하류 승차/하차 쌍을 생성한다.
3. 120초 이내 실시간 관측과 최대 30초 미래 오차만 유효하게 사용하고, 없으면 시간표로 되돌린다.
4. 실제 운행 시간이 없는 데이터에는 배차 window와 정류장 누적 시간을 이용해 추정 운행을 생성한다. 첫·마지막 출발 범위를 넘지 않으며 추정임을 표시한다.
5. 출발 시간대마다 도착 시각 우선 탐색한다. 다음 구간 출발은 이전 하차+도보+여유 이후여야 한다. 첫 구간에는 환승 여유를 더하지 않는다.
6. 모든 노선의 후속 차량도 탐색한다. 이미 지난 환승 차량을 억지로 연결하거나 현재 ETA를 단순 합산하지 않는다.
7. 동일 차량 재탑승과 방문 정류장 순환을 제외한다. 4시간 탐색 범위, 1만 상태 확장, 큐 2만, 시간대별 최대 12개 결과를 적용하고 제한 도달 여부를 반환한다.
8. 목적지 도착 시각·소요·대기·도보·환승 횟수와 구간별 차량 키·시간 근거를 반환한다. 대기에는 환승 여유가 포함되고 도보는 별도로 계산된다.

최초 버전은 정류장 직접 선택이다. 장소 검색·첫 정류장까지 도보, 요금·교통약자 경로·복잡한 다중 환승 최적화는 추가 구현 대상이다. 데이터 규모에 따라 사전 인덱싱과 RAPTOR 등으로 엔진을 확장할 수 있다.

## 선택·상태 전이

`waiting → riding → transfer → riding → completed`가 기본 흐름이다. 첫 승차와 환승 대기는 사용자가 탑승 확인하면 riding으로 전환한다. 하차 확인 시 다음 구간이 있으면 transfer, 없으면 completed다. 놓침·연결 불가는 disrupted, 사용자 종료는 cancelled다.

진행 변경은 본인 세션 ID와 revision을 요구한다. 경로 결과는 10분 동안 본인만 선택할 수 있다. 재탐색은 현재 대기 정류장에서 목적지까지 후보를 만들며 기존 세션을 자동 교체하지 않는다. 사용자가 기존 이동을 종료한 뒤 새 후보를 시작한다. 탑승 중 재탐색은 현재 하차 위치를 확정하지 못하므로 허용하지 않는다.

위치 권한 없이 수동 탑승·하차로 진행한다. 이전 런타임의 30m geofence 로직은 새 화면에 연결하지 않는다.

## 알림

Ubuntu 서버가 15초마다 활성 세션을 평가한다. 앱도 15초마다 현재 세션과 미확인 알림을 조회한다. 현재 대기 구간 또는 탑승 중 다음 환승 구간에서 선택 차량의 도착이 0~300초 이내이면 알림 outbox를 생성한다. 이미 5분 이내인 이동도 즉시 평가한다.

다음 환승 구간은 앞 구간의 갱신된 도착 시각·도보·여유를 계산해 연결 가능성을 확인한다. 지난 차량과 연결 불가 구간은 알림을 내지 않고 disrupted로 전환한다. 시간표·배차 추정도 근거 라벨을 함께 보낸다. 지연이 반영된 목적지 도착 시각을 세션에 갱신하되 다른 버스로 자동 변경하지 않는다.

앱은 사용자가 알림 권한을 켠 경우 로컬/브라우저 알림을 표시하고, 항상 앱 내 안내를 표시한다. 알림 수신 확인은 별도 ack 요청이다. 전송 실패 시 재조회할 수 있으며 클라이언트의 실행 중 메모리 캐시와 고정 알림 ID로 중복을 줄인다. 정확히 한 번의 기기 전달을 보장하지는 않는다. 상태 변경 시 이전 미확인 알림을 취소 처리한다.

앱 프로세스 종료 후 원격 푸시는 이 구현에 포함하지 않는다. APNs/FCM/Web Push 자격증명과 발송 어댑터가 필요하다. 서버가 outbox를 생성하는 것과 실제 기기에 알림이 전달되는 것을 구분한다.

## API

모든 경로는 `/bustimer` 접두사 아래에 있다. `/health` 외 API는 Bearer 인증을 요구한다.

| 메서드·경로 | 입력·동작 |
|---|---|
| GET /api/journey-stops?q=검색어 | 이름/ID로 최대 100 정류장 |
| POST /api/journeys/search | originStopId,destinationStopId,departureAt,compareCount,compareStepMinutes,maxTransfers,bufferSeconds |
| GET/POST /api/saved-journeys | 본인 목록 / name,originStopId,destinationStopId,weekdays,departureTime |
| DELETE /api/saved-journeys/:id | 본인 저장 삭제 |
| GET/POST /api/journey-sessions | 활성 목록 / optionId로 이동 시작 |
| GET /api/journey-sessions/:id | 최신 연결 평가·상태 조회 |
| POST /api/journey-sessions/:id/action | action(board,alight,missed,cancel),revision |
| POST /api/journey-sessions/:id/replan | 현재 승차 정류장에서 재탐색 |
| GET /api/journey-sessions/:id/alerts | 본인 미확인 유효 알림 |
| POST /api/journey-sessions/:id/ack | ids 배열 |
| POST /api/catalog | 관리자 전용 정규화 데이터 upsert |

잘못된 입력 400, 인증 실패 401, 타인 세션/없는 정류장 404, 결과 만료·상태 충돌 409를 반환한다. 데이터가 없으면 빈 후보를 반환하고 샘플을 실운행으로 대신하지 않는다.

## 인증·공급자 연동

관리자는 서버 CLI로 사용자별 기기 토큰을 발급한다. SQLite에는 SHA-256 해시만 저장한다. 신규 API는 토큰으로 user_id를 결정하고 클라이언트의 userId를 신뢰하지 않는다. API_BEARER_TOKEN은 관리자 import와 이전 API 전용이며 앱에 넣지 않는다. 초기 앱은 기기 토큰을 메모리에만 보유하므로 재실행 시 재입력이 필요하다.

운영 CORS 기본값은 `https://app.bluewaikiki.top`이다. 경로 `/ledger/` 또는 `/bustimer/`를 Origin에 포함하지 않는다. 본문은 4MiB로 제한한다. 공개 출시 전 계정 인증·기기 등록 UX, 요청 제한과 토큰 재발급·철회 UI를 보완해야 한다.

지역 제공자를 확정하기 전까지 관리자 import 계약으로 분리한다. 공급자 수집기는 정류장·방향별 노선·운행일별 시간표·배차·환승 연결과 실시간 예측을 정규화해 적재해야 한다. 외부 제공자를 정하지 않은 현재 상태에서 실운행 경로와 알림의 운영 완료를 주장하지 않는다.

## 구현 상태

구현: 추가 DB 마이그레이션, Node 실행부, Docker·Caddy 설정, 경로 엔진, 저장 경로, 세션·수동 상태 전이, 구간 알림 outbox, Flutter 검색/비교·저장·진행·알림 화면.

미연결: 지역 실시간 공급자/수집 스케줄러, 장소 검색, 앱 종료 원격 푸시, 계정 온보딩·영속 토큰 저장, 실기기 및 실노선 검증. 웹/모바일 알림 정책의 정확한 지원 범위는 실제 기기 확인이 필요하다.
